### **✨2차 과제 내용:**
(예시)
  이번 2차 과제는 1차에서 기획한 '스마트 캠퍼스 가계부'의 기초 뼈대에 살을 붙여, 실질적인 데이터 필터링과 예산 경고 시스템을 구축하는 것입니다.

사용자로부터 목표 예산과 위험 경고 비율(float)을 입력받은 뒤, for 반복문을 통해 여러 건의 지출 내역을 리스트에 저장합니다.

이때 if-elif-else 다중 조건문과 break, continue를 활용하여 잘못된 입력(음수)은 걸러내고 조기 종료(0 입력)가 가능한 흐름 제어 로직을 구현했습니다.

입력이 끝나면 리스트 내장 함수(len, sum, max)를 이용해 통계를 내고, 관계/논리 연산자(and, <=)를 활용하여 잔여 예산 비율에 따라 [경고], [주의], [안전] 3단계로 상태를 진단하여 출력합니다.
    
### **🤖 AI 파트너십 과정**
(예시) 
프롬프트 요약: "가계부에서 지출 금액을 연속으로 입력받을 때, 사용자가 실수로 음수를 넣거나 중간에 입력을 그만두고 싶을 때 어떻게 처리하는 게 좋을까? 배운 내용 중 break와 continue를 활용해서 로직을 짜줘."

적용 내용: AI의 조언을 받아 for문 내부에 if-elif-else를 중첩했습니다. 0을 입력하면 break로 즉시 루프를 빠져나가고, 음수를 입력하면 continue로 리스트 추가 없이 다음 반복으로 건너뛰도록 하여 견고한 예외 처리 로직을 완성했습니다.

내용 2: 리스트 함수 및 복합 연산자 최적화 자문

프롬프트 요약: "리스트에 지출 내역을 저장(append)하면서, 동시에 남은 예산을 계산해야 해. sum() 함수를 쓰는 것과 복합 대입 연산자(-=)를 쓰는 것 중 어느 것이 직관적일까?"

적용 내용: 두 가지 방법을 모두 융합하는 아이디어를 얻었습니다. 반복문 안에서는 current_budget -= expense를 사용하여 매 순간의 잔고를 실시간으로 차감하고, 최종 통계 출력 시에는 sum(expense_list)와 max(expense_list)를 사용해 리스트의 내장 함수 활용도까지 극대화했습니다.
    
### **🛠️ Troubleshooting & 기술 회고:**
문제 1: 예산 잔여 비율 계산 시 ZeroDivisionError 발생 위험

원인: 초기 목표 예산(initial_budget)을 사용자가 0으로 입력할 경우, remain_ratio = current_budget / initial_budget 수식에서 0으로 나누게 되어 런타임 에러가 발생할 수 있음을 깨달았습니다.

해결: 이번 과제의 범위를 넘어서는 복잡한 예외 처리 대신, 가계부의 특성상 예산은 자연수라는 전제하에 입력 단계 안내 문구를 수정하고, valid_count > 0 이라는 독립적인 if문을 감싸서 안전하게 출력되도록 로직의 순서를 재배치했습니다.

문제 2: continue의 오작동 및 데이터 누락

원인: 처음에는 지출 내역을 리스트에 append 하는 코드를 if문 보다 먼저 적어버려서, 음수를 입력해도 리스트에 값이 들어간 뒤에 continue가 실행되는 논리적 오류(Logic Error)가 있었습니다.

해결: continue 명령어는 '그 아래의 코드를 실행하지 않고 반복문의 처음으로 돌아간다'는 명확한 규칙을 AI와의 문답을 통해 재확인했습니다. 데이터 저장(append 및 -=) 코드를 else 구문 안으로 가장 마지막에 배치하여 문제를 깔끔하게 해결했습니다.

### **🛠️ Troubleshooting & 기술 회고:**
  문제 1: 함수 내부에서 예산 변수를 수정할 때 발생한 에러 (UnboundLocalError)

원인: add_expense 함수 안에서 current_budget -= amount를 실행하려 했으나, 파이썬은 해당 변수를 함수 내부의 '지역 변수'로 착각하여 할당되기 전에 참조했다는 에러를 뱉어냈습니다.

해결: AI를 통해 변수의 유효 범위(Scope) 개념을 학습했습니다. 함수 외부에서 선언된 current_budget을 함수 안에서 수정하려면 global current_budget 이라고 명시하여 "이 변수는 전역 변수다"라고 선언해 주어야 함을 깨닫고 코드를 수정해 해결했습니다.

문제 2: 메뉴 선택 시 잘못된 데이터 타입으로 인한 분기 오류

원인: choice = input()으로 받은 값은 문자열인데, 처음에는 if choice == 1: 처럼 정수형과 비교하여 메뉴가 작동하지 않고 계속 else로 빠졌습니다.

해결: 입력받은 문자열을 형태 그대로 if choice == '1':과 같이 따옴표를 씌워 문자열로 비교하도록 수정하여 형변환(int()) 시 발생할 수 있는 에러를 방지하고 정상 작동시켰습니다.

  * 내용. 이번 V3.0 업데이트의 핵심은 단순한 금액 누적을 넘어, 언제(날짜), 어디에(카테고리), 얼마(금액)를 썼는지 구체적으로 기록할 수 있도록 이중 리스트(2D List) 구조를 도입한 것입니다.

이중 리스트에 누적된 데이터는 가독성을 위해 인덱싱(record[0], record[1] 등)을 활용하여 표 형태로 깔끔하게 출력하도록 개선했습니다.

프로그램 종료 시 데이터가 휘발되는 것을 막기 위해 open() 함수를 사용하여 .csv 파일 형식으로 저장하고 불러오는 파일 입출력 로직을 추가했습니다.

사용자의 오타나 파일 누락 등으로 인한 프로그램 비정상 종료를 방지하기 위해 2가지 상황에 대한 try-except 예외 처리를 적용했습니다.

### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** ... 이중 리스트 반복 출력 시 데이터 포매팅 문제
     * **원인:** ... for record in expense_data:를 사용해 출력할 때 데이터 형태가 리스트 ['11/05', '식비', 5000] 그대로 화면에 출력되어 가독성이 매우 떨어졌습니다.
     * **해결:** .. 리스트 내부의 각 요소에 접근하기 위해 리스트 인덱싱 기법을 학습했습니다. record[0], record[1], record[2]와 같이 개별 데이터를 꺼내고, f-string의 정렬 기능(<6)을 결합하여 엑셀 표처럼 깔끔하게 출력되도록 로직을 수정했습니다.

     문제 2: 파일에서 데이터를 읽어올 때 금액 계산 오류 (TypeError)

원인: csv 파일에서 텍스트를 읽어와 date, category, amount 변수에 쪼개어 담았으나, 잔여 예산(current_budget)에서 amount를 뺄셈할 때 문자열과 숫자는 뺄 수 없다는 에러가 발생했습니다.

해결: 텍스트 파일(.csv)에서 읽어온 모든 데이터는 기본적으로 문자열(string) 속성을 가진다는 점을 깨달았습니다. 따라서 리스트에 다시 저장하고 계산에 활용하기 전에 int(amount)를 통해 정수형으로 형변환하여 문제를 해결했습니다.
